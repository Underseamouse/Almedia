# Аудит дизайн-системы

Прогон по скиллу `design-design-system` (Audit Mode): hardcoded-значения, нейминг,
дубликаты, недостающие состояния, a11y. Сверка с `design-system/*.pdf`,
с `freecash-onboarding-build-brief.md` и с живым freecash.com.

Что и откуда построено — в [design-system.md](design-system.md). Здесь только расхождения.

> **Статус: все находки закрыты.** Ниже — что было найдено и чем починено.
> Итог после починки: 16 компонентов, 77 вариантов, несвязанных значений — 0
> (кроме 37 брендовых цветов Apple/Google/Facebook, это осознанное отклонение).
> Оба провала контраста устранены, 4 недостающих компонента собраны.

## 1. Hardcoded-значения

Заливки, обводки, радиусы, паддинги, gap и высоты привязаны к переменным.
Осталось несвязанного:

| Что | Где | Вердикт |
|---|---|---|
| Брендовые цвета Apple/Google/Facebook (10 значений) | Social Button | Осознанно. Требование провайдеров, зафиксировано в description компонента |
| `strokeWeight` 1 / 2 / 4 | все компоненты с обводкой | **Пробел.** Нет токенов толщины обводки — значения набиты руками |
| Высота трека 8px | Progress Bar | **Пробел.** Нет токена, хотя это системная величина |
| Кольцо 48px + stroke 4 | Loader | **Пробел.** Размер не из `size/*` |
| Указатель 16×8 | Tooltip | Допустимо — геометрия фигуры, не токен |

**Рекомендация:** завести коллекцию `Border` (`border/thin` 1, `border/thick` 2,
`border/ring` 4) и добавить `size/track` 8, `size/loader` 48.

## 2. Нейминг

| Проблема | Детали |
|---|---|
| Коллекция `Radius` содержит переменные `rounded/*` | Единственная коллекция, где имя не совпадает с префиксом токенов (`Spacing`→`spacing/*`, `Size`→`size/*` — совпадают). Переименовать коллекцию в `Rounded` |
| Регистр в именах компонентов | `Input field`, `Alert row` — со строчной; `Selector Card`, `Tab Bar Item`, `Social Button`, `Pill Selector`, `Progress Bar` — Title Case. Привести к Title Case |
| Свойство `Style` означает разное | Button — визуальная иерархия; Badge — семантический тип; Alert row — severity; Progress Bar — цвет. Переименовать: Badge → `Type`, Alert row → `Severity`, Progress Bar → `Tone` |
| `Primary/Gray Blue/Transparent` | Имя не описывает значение (#141523 @ 80%). В PDF так и написано («Trabsparent», с опечаткой). Оставил как в источнике — но стоит уточнить у Freecash |

## 3. Дубликаты и почти-дубликаты

- **Pill Selector ≈ Button (Secondary/Outline)** — одинаковая геометрия (h44, radius 8,
  padding-x 20). Отличие смысловое: Button — действие, Pill Selector — выбор с
  залипанием. Не сливать, но нужна строка «когда что» в документации.
- **Selector Card ≈ Pill Selector** — оба «выбери один вариант». Оба реально есть в
  приложении (карточки в квизе, пилюли на экране оффера), так что оправдано;
  правило: ≥3 вариантов или длинный текст → Card, бинарный выбор → Pill.
- **Badge (Rating) ≈ Tab Bar Item (Active)** — оба тонированные пилюли. Разное
  назначение, коллизии нет.

## 4. Недостающие состояния

| Компонент | Есть | Нет |
|---|---|---|
| Button | Default, Pressed, Disabled | **Hover**, **Focus**, **Loading** |
| Social Button | — | **Pressed**, **Disabled**, **Loading** (нет ни одного состояния) |
| Input field | Default, Focused, Error | **Disabled**, **Filled** (значение vs плейсхолдер) |
| Selector Card | Default, Selected | **Disabled**, **Focus** |
| Pill Selector | Default, Selected | **Disabled**, **Focus** |
| Tab Bar Item | Active, Inactive | достаточно |
| Badge, Avatar, Tooltip, Alert row, Progress Bar, Loader | — | по природе без состояний |

`Loading` для Button и Social Button — не косметика: в build-brief Screen 13 весь
вход построен на соц-кнопках, а ожидание ответа провайдера нечем показать.

## 5. A11y

Контраст считался с учётом альфы поверх `surface/background`.

**Провалы WCAG AA (текст ≥4.5:1):**

| Пара | Ratio | Где | Починка |
|---|---|---|---|
| `status/error` на фоне | **3.88** | Alert row Error, хелпер ошибки в Input | `Primary/Error/300` → **6.53** (на container 5.40). Error/400 не годится: на container 3.99 |
| `text/primary` на `Information/500` | **3.00** | Badge Rating | Сделать тонированным, как два других беджа: фон `Information/25`, текст `Information/400` → **7.54**. Чинит и контраст, и несогласованность |

**Тач-таргеты:** Button `Size=Small` — высота **38px** при минимуме 44 (iOS HIG,
WCAG 2.5.5). 9 вариантов. Значение взято с freecash.com, то есть проблема
унаследована от продукта — но для мобильного онбординга это реальный риск.
Рекомендация: Small оставить для веба, в мобильных экранах использовать Medium (44).

**Не провалы, но под запись:**
- Disabled-кнопки 3.08 / 3.78 — WCAG 1.4.3 выводит неактивные контролы из-под
  требования, оставляю осознанно.
- Facebook 4.27 — брендовый цвет, изменить нельзя.
- Остальные пары в норме: `text/primary` 18.1, `text/secondary` 7.9,
  `action/primary` 9.4, `status/warning` 11.6.

**Прочее:** ни у одного компонента нет `Focus`-состояния → навигация с клавиатуры
на вебе не показана. Иконки — плейсхолдеры-эллипсы, при сборке экранов нужны
реальные иконки с текстовыми подписями (не только цветом различать состояния).

## 6. Компонентов не хватает под build-brief

`freecash-onboarding-build-brief.md` §3 требует 6 глобальных компонентов. Есть 2:

| Из брифа | Статус |
|---|---|
| A. Coin Voice | **нет** — рассказчик всего флоу, есть почти на каждом экране |
| B. Progress bar | есть |
| C. Earnings Meter | **нет** — ключевая механика R5 (прогресс к гарантированной награде) |
| D. Single-choice card | есть (Selector Card) |
| E. Offer card | **нет** — Screen 14, главный фикс всего редизайна |
| F. Stat block | **нет** — Screen 0, доверие |

Спека Offer card снята с freecash.com и готова к сборке: карточка radius 15,
фон `surface/container`, превью 87×87 radius 6, тайтл 12/600 белый, подзаголовок
12/500 `text/secondary`, лейбл «UP TO» 12/500 `text/secondary`, сумма 16/600 белая,
дробная часть 13/600, рейтинг-бедж 10/700 на градиенте.

**Дополнительно замечено на сайте и в приложении, но не построено:**
Icon Button (40×40), сегментированные табы (Cashout / My Withdrawals),
контейнер нижней навигации, шапка экрана, тайл выплаты (PayPal $5 / $10),
FAQ-аккордеон, модальное окно.

## 7. Несогласованности самого Freecash (не мои — на заметку команде)

- Рядом с именованной шкалой `rounded-01…07` на сайте живут произвольные
  `15px`, `6px`, `10px`, `30px` — в том числе 15px на главной offer-карточке.
- `Secondary/Gray` в Colors.pdf побайтово повторяет `Secondary/Blue`.
- Лейбл нижней навигации: «Rewards» против «Quests» (уже зафиксировано в PRD, R13).
- Паддинг offer-карточки задан как `2.5vw` — плавающая величина вне шкалы отступов.

## Что сделано по итогам аудита

**A11y — оба провала закрыты**
- Добавлен `text/error` → `Error/300`: **6.53:1** на фоне, **5.40:1** на контейнере
  (было 3.88). `Error/400` проверен и отвергнут — на контейнере даёт 3.99.
  `status/error` остался для заливок и обводок, где контраст текста не при чём.
- Добавлены `text/warning` → `Warning/500` (11.56) и `status/info` → `Information/400`.
- Badge Rating переведён на тонировку `Information/25` + текст `status/info`:
  **7.54:1** (было 3.00). Заодно бедж стал согласован с Streak и Balance.
- Тач-таргет: `Size=Small` (38px) оставлен как есть — это реальное значение
  freecash.com — но в description компонента прямо написано, что он для веба,
  а в мобильных экранах брать `Medium` (44px).

**Состояния — добавлены**
- Button: + `Focus` (внешнее кольцо `action/primary`) и + `Loading` (спиннер вместо
  подписи) → 30 вариантов. `Hover` сознательно не добавлен: продукт mobile-first,
  и Focus (клавиатура, ассистивные технологии) важнее указательного состояния.
- Social Button: было 0 состояний → `Default / Pressed / Disabled / Loading` × 3
  провайдера = 12 вариантов.
- Input Field: + `Filled` (реальное значение vs плейсхолдер) и + `Disabled` → 5.
- Selector Card и Pill Selector: + `Focus`, + `Disabled` → по 4.

**Недостающие компоненты — собраны все четыре**
- **Stat Block** (§3.F) — иконка + число + подпись, Tone = Gold / Neutral.
- **Offer Card** (§3.E) — Type = Guaranteed / Estimated. Тип-шкала снята с реальной
  карточки freecash.com; радиусы 15 и 6 с сайта нормализованы в `rounded/04` и
  `rounded/02`, потому что они выпадают из собственной шкалы Freecash.
- **Earnings Meter** (§3.C / R5) — State = Progress / Complete, формула
  `(отвечено / 7) × 40.00 zł`, в description зафиксировано, что сумма фиксированная.
- **Coin Voice** (§3.A) — Mood = Neutral / Celebrating, собран из брендовой монеты,
  а не из нового маскота (обоснование в description).

**Токены и нейминг**
- Новая коллекция `Border`: `border/thin` 1, `border/thick` 2, `border/ring` 4 —
  34 толщины обводок переведены с чисел на токены.
- Добавлены `size/track` 8, `size/loader` 48, `size/thumb` 87.
- Коллекция `Radius` → **`Rounded`** (совпадает с префиксом `rounded/*`).
- `Input field` → `Input Field`, `Alert row` → `Alert Row`.
- Свойство `Style` разведено по смыслу: Badge → `Type`, Alert Row → `Severity`,
  Progress Bar → `Tone`.
- Дубликаты не сливались: Selector Card и Pill Selector реально существуют в
  приложении. Вместо этого правило «когда что» записано в description каждого
  (≥3 вариантов или переносимый текст → Card, бинарный выбор → Pill).

**Осталось открытым (осознанно)**
- 37 несвязанных значений — брендовые цвета Apple / Google / Facebook.
- Замечания к самой системе Freecash из раздела 7 — это вход для команды продукта,
  а не наша правка.
- Компоненты, замеченные на сайте, но не входящие в онбординг-флоу (FAQ-аккордеон,
  модалка, сегментированные табы, тайл выплаты) — вне рамок задания.
